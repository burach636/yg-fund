# YG Fund – fundraising web app for Yeshivas Maharit D'Satmar

## Talk to the user in Yiddish
The owner speaks Yiddish (Hasidic spelling, with English loanwords) and is not technical. Reply in Yiddish. Give short, numbered, click-by-click steps. Code, comments and commit messages are in English. The whole UI is Yiddish/Hebrew, right-to-left (RTL).

## What this is
A static web app (no build step) hosted on **Netlify**, at https://yeshivasmaharitdsatmar.netlify.app.
- Netlify should auto-deploy this repo from the root folder. There is no build command, and the publish directory is the root.
- After a change is pushed, the site updates in about a minute. Tell the user to press Ctrl+F5.

Backend is **Supabase** (project `qrudivrakwoathgbzrwd`).
- `config.js` holds the project URL and the **publishable** key. That key is public by design; security comes from Row Level Security.
- **Never** put a `service_role` or `sb_secret_` key in this repo.

`SETUP.sql` is the database schema. The user already ran it. If you change the schema, give the user a new SQL snippet to paste into **Supabase > SQL Editor > New query > Run**.

## Data model
- **JLS Solutions** (the user's existing Windows donor software) stores everything in an Access/Jet 4 file, `Tuition.mdb` (~460 MB).
  - The user drags that file into the app (header button "דערהיינטיג פון JLS").
  - `jls.js` parses it **in the browser**. It is a pure-JS Jet 4 reader, tested on the real file.
  - The parser extracts a slim dataset: all accounts (names in English and Hebrew, default address, phones), plus payments and pledges **only for company 32 = "YG Fund"** (pledge index 11 = DateE, entry date). Accounts get `em` (e-mails: MPhone values with @ and MAInfo values that look like e-mails). Also `udf` ([code, type, value] from MAInfo, only UDF* types) and `camphits` ([campaign, code, 1 paid | 2 pledged] for all companies, last ~4 years).
  - The dataset is gzipped and uploaded to Supabase Storage at bucket `jls`, file `jls.json.gz`. Table `jls_meta` holds a version counter, and clients reload when it changes.
  - Real numbers from the file: 21,104 accounts, 8,111 YG payments, 4,365 YG pledges, 1,380 YG donors (564 of them gave only once).
- **NEVER** read or import the JLS tables `CCTransactions` or `MChecking`, the columns `Members.SSNumF` and `Members.SSNumW`, or the tables `Users` and `MWebLogin`. These hold card, bank, SSN and password data.
- `MCCInfo` (recurring credit-card plans): the owner explicitly allowed (2026-11) reading **only** `Code, ChargeFreq, StartDate, EndDate, Amount, CampaignNum, TempOnly`, filtered by `CompanyNum`, into `JD.ccplans`. **Never** decode `CCNum, Name, ExpDate, Last4, TrackInfo, Address, Zip, Note, Comments, CreditID` or any other column. The Jet reader decodes only the columns listed, so keep that list exact. Reports project the upcoming charges (`ccCharges`, 24 months ahead) in green.
- **App data** (to-dos, notes, call marks, assignments, settings) is an append-only event log in table `events`, with columns (k, eid, p jsonb, by, at).
  - Clients replay the log with `applyEvent`. The rule is `state[k][eid] = Object.assign(state[k][eid] || {}, p)`.
  - Event kinds: `acct` (per-account settings: freq, nextAsk, assigned, vip, notes, lastAsk, shul, tags[], email), `task`, `fr`, `frin`, `frex`, `shul`, `rcpt` (printed, ed = hand-edited receipt text, emailed, emailTo), `frmail` (office e-mail sent per fundraiser period), `frexp` (dinner expenses), `stmt` (id = code: sent, bal), `tust` (tuition statements, id = code), `jrep` (report definitions), `call` (id = `code|YYYY-MM`), `hist` (notes/history), `settings` (id `s`).
  - Clients poll every 15 s.
- **Users**: Supabase Auth with email and password.
  - Access is allowed only for emails listed in table `team` (email, name, is_admin). RLS uses `is_team()` and `is_admin()`.
  - The admin manages `team` from the app's Settings page.
  - Section access: `team.perms text[]` (SETUP.sql section 7; null = everything, admins always everything). `SECTIONS`, `canView(v)`, `applyPerms()` in app.js hide nav buttons, home tiles and home columns; `go()` refuses. Settings > users table > "🔒 Access" (`permForm`): first which part – both / 🎓 tuition only (`perms = ['tuition']`) / 💵 fundraising only (fund sections without 'tuition') – then which fundraising sections; `permLabel` shows e.g. "🎓 Tuition only". If the area picked at login is not allowed, `start()` opens the allowed one with a toast. This is UI-level hiding: all team members can still read the event log and the JLS file through RLS.
  - The free plan's email sending is rate-limited. To add a user without email, use **Supabase > Authentication > Users > Add user > Create new user** with **Auto Confirm User** checked.

## Files
- `index.html`: the page shell. It loads supabase-js from the jsdelivr CDN, then `config.js`, `jls.js`, `cal.js`, `xlsx.js`, `sections.js`, `receipts.js`, `tuition.js`, `jreports.js` and `app.js`.
- `sections.js` (v1.2, loaded before app.js, functions only): Home dashboard (default view `home`), To-Do list (`todo`), fundraiser accounts (`fund`), shuls (`shuls`).
  - Tasks: `who` + optional `who2` (two users); `priv: true` + `owner` (email) = private. Always write tasks via `emitTask`, which keeps priv/owner on every event. SETUP.sql section 5 makes RLS hide priv events from others.
  - Fundraisers: `fr` events (payments to them), `frin` (income not in JLS), `frex` (amounts with no percentage, subtracted from that period's income before the %). Settings `frPct` (default 40), `frStart` (default RH 5787 = 2026-09-12). Income = JLS payments (not refunded) from frStart; 14-day periods from frStart.
  - 🍽️ Dinner expenses: event kind `frexp` {date, vendor, desc, amt, file {path, name, type, size}, del}; invoices in Storage `jls/invoices/<id>-<ms>.bin` (octet-stream, 3 tries), opened with `expOpen` (download → Blob URL with the saved type). Expenses belong to a **Jewish year** (`hy`, chosen in the form, default from the date); that year's income first covers that year's expenses and only the rest earns the fundraisers' % (periods belong to the year they start in; `p.exp` = amount taken off in that period, `F.expYears[hy] = {total, covered, left}`), the same in the server `fundmail` function; the section shows one year at a time (chips, `ui.expY`); search box `ui.expQ`, total, Excel; e-mail templates know `{expenses}`.
  - ✉️ Office e-mail per 2-week period (`frMailForm(k)`, `frMailGo`): asks the office to write checks for the fundraisers' % of that period; To = setting `frOffice`, optional CC = `frCc` (several addresses with commas), subject/body templates `frMailSubject`/`frMailBody` with {from} {to} {count} {income} {exempt} {pct} {amount} {paid} {balance}; an Excel (summary + donors with their gifts + payments, `donorRows`) is attached. Sent marks: event kind `frmail` (id = period start). Every 2 weeks `ensureFundMailTask` adds a to-do (id `frmail-<from>`, `fm: {from, to}`) for setting `frMailWho`.
  - Shuls: `shul` events (name, addr, notes, ord, paused, del). Setting `shulStart` (a Wednesday); every 14 days the next active shul in `ord`. Per-account `acct.shul`.
- `app.js`: all UI and logic. Views:
  - Today (to-do list, auto "ask again" schedule)
  - Monthly pledges (call list that resets each month)
  - Accounts / "נדבות" (search across all ~21k; default filter YG donors; default sort A-B by Hebrew last name `lh` = JLS `LNameH`, falling back to the last word of the Hebrew name until a re-import)
  - Account modal (payments, pledges, history, tasks, per-account settings); "✉️ אימעיל" sends a plain e-mail with own subject/text and optional CC (`acctMail`, receipts.js), logged in the history
  - Reports: totals per Jewish year with a box per Hebrew month (13 in leap years) and the year total; click a month (or the total) for its donors (`monthDonors`, Excel `xlsMonth`); optional "scheduled" amounts (`expPledges`: open JLS charges, not on hold, due from today on – this is where scheduled credit-card installments show up) shown in green per month; Excel `xlsReports` (5 sheets)
  - Settings (admin only)
  - Login, signup, password recovery, and a setup self-check screen
- `cal.js`: Hebrew calendar helpers (Intl `en-u-ca-hebrew`), Hebrew numerals, and a dual Hebrew/English date picker. Use `dateField(id, value, {clear})` together with `initDateFields(root)`. The `modal()` function calls it automatically.
- `receipts.js` (view `rcpt`): printable receipts copied from the user's Word mail-merge template. `receipt-bg.jpg` is the template's background image; `RC_BOX` holds the exact text-box positions (inches) from the .docx. One Letter page per JLS payment, opened in a new window and printed. Printed marks: event kind `rcpt` (id = PaymentNum). Every 2 weeks (same periods as the fundraisers) `ensureRcptTask` adds a to-do with fixed id `rcpt-<periodFrom>` and `rc: {from, to}`. Settings `rcptBy`, `rcptSuffix`, `rcptWho`.
  - The view is "רעסיטס/סטעיטמענטס" with two tabs (`ui.rcTab`). Receipt items come from `rcItems()`: payments, except campaigns in setting `rcptPlCamps`, whose **pledges** become the receipts (key `pl<ChargeNum>`, date = pledge entry date). ✏️ per receipt saves `rcpt.ed` overrides (top, amt, date, heb, eng, a1, a2, by). Search box (`ui.rc.q`: name/phone/#code/amount) looks in all years and shows printed ones too; 🖨️ prints a single receipt again (`rcPrintOne`), also from the donor's payments tab (`rcPrintPay`); chips for last year / all years.
  - Statements tab (`vStmt`): donors with open, not-on-hold pledges (filter by campaign, due-now/all, minimum); one Letter page each (logo, address, table, editable text `stmtTitle`/`stmtText`); "mark sent" writes `stmt` + a history note.
- `jreports.js` (view `jrep`, "רופארטס"): call lists = accounts with a UDF value (MAInfo) who did not pay or pledge to a campaign in any company (`JD.camphits`), optional tag. Default report `r983`: UDF4 in 1,2,3, not campaign 983 "dinner maharit 2026". Results have a search box (`ui.jrQ`) and a who-calls filter (`ui.jrWho`: all / `__me` / `__none` / a user name). Also the 🏷️ tag helpers (`tagsOf`, `tagChips`, `tagEditor`, `tagToggle`); `PRESET_TAGS` = the owner's fixed list of flags, shown as quick buttons on every donor and first in every tag list; `TAG_RENAMES` + `tagMigrate()` rename flags whose wording changed.
- **Two areas (v1.16)**: the login screen first asks which part to open (`vLogin()` without `AREA` shows two boxes, `preArea(a)`, "⇄ ענדערן" = `vLogin('choose')`; `logout()` clears it). If a session starts without an area (new tab), `vChooser()` shows the same two boxes after login: 🎓 שכר לימוד (`AREA = 'tu'`) and 💵 פאנדרעיזינג (`'fund'`); kept per tab in sessionStorage `yg_area`; header button `#btnArea` switches (`setArea`, `chooseArea`). Nav buttons carry `data-a="fund"|"tu"` (Settings has none = both). Tuition views `TU_VIEWS = thome, tuition, tubill, tustmt` + `todo`; `canView()` maps all of them to the permission `tuition` (`canFund()` = has any non-tuition perm). Tasks made in the tuition area get `area: 'tu'`; `taskVisible` shows only the current area's tasks (no area = fundraising). The tuition area has no fundraiser accounts and no shuls.
- `tuition.js` (tuition area; JLS company setting `tuitionCompany`, default 15 = "TCYG", 0 = off). `JLS.extract(bytes, co, progress, {tuition})` adds `tuition` = {co, name, payments [num, code, date, amt, type, check, notes, refunded, period, studentNum (PStudentNum), receiptNum], charges [num, code, due, amt, paid, bal, desc, hold, note, entered, studentNum (CStudentNum), period, itemNum] = the monthly bills, contracts [id, code, start, end, item, desc, amt, type, period, studentNum (CompanyStudents), scholarship, notes, payment] from **MYearly** (the yearly contracts made every Tishrei), students [num, code, fname, lname, fnameH, lnameH, class, start, end] (families/students with activity in that company; family = `Students.Code` number, else `FamilyNum`)} – **all years**. **Students: never decode SSNum, DOB, medical, bus, LegalFName or any other column.** `doImport` uploads it separately as `jls/jls-tuition.json.gz`; `loadTU()`/`tuReady(v)` load it when a tuition view opens (reload when `jlsVersion` changes).
  - `vTuHome` (dashboard: parents, Billing this Jewish year, paid, due now, statements; columns To-Do / owes most / last payments). `tuCalc()` per family: billed/paid this Jewish year (school year = Jewish year), balance, due now (open, not on hold, due ≤ today), `cur` (current student/contract/charge this year).
  - `vTuition` "👨‍👦 עלטערן און תלמידים": search `ui.tuQ`, chips cur/due/bal/all (`ui.tuF`), who calls `acct.tuWho` (filter `ui.tuW`), sort `ui.tuSort`, 📝 notes (shared `hist`); family modal `tuFamily` (students, contracts, bills of all years, payments, history, statement, e-mail, To-Do, Excel).
  - `vTuBill` "🧾 Billing": every Jewish year, a box per Hebrew month (billed / 💵 paid / open), click → `tuMonth(hy, m)` families (Excel `tuMonthXls`); `tuBillXls`.
  - `vTuStmt` "📄 סטעיטמענטס": one page per family for one Hebrew month (`ui.tuSt.ym`), laid out like the owner's JLS report "Statements TCYG" (C1Report XML they sent): title "שכר לימוד סטעיטמענט", "~ חודש X ~", students + class, lines = חוב ישן (charges not on hold before the month − payments before it) + that month's bills (ItemNum - Period, student) and payments (Check #), נשאר חוב, Old Balance / Current Year Balance, boxes ס"ה די חודש (items × count), חוב פער תלמיד (open BalanceDue per student), contact text and bottom text (settings `tuStText`, `tuStNote2`, `tuSuffix`; defaults are generic – the repo is public, so no staff names/cell numbers in code), Total Balance. ## UX rules the user asked for
- The nav button for the home view is "🏠 Dashboard" (class `navhome`), larger and highlighted.
- Login screen: the yeshiva building as background (`building.jpg` wide and `building-m.jpg` phone, both made from the owner's landscaped photo – flowers, no big trees in front – with a warm sun glow added; no generative editing is available here), dark gradient overlay, translucent login box.
- Automatic log out after **10 minutes** without mouse/keyboard/touch (`IDLE_MS`, last activity in localStorage `yg_act`, shared by all tabs; a warning toast 1 minute before; skipped while the busy overlay is on). Also checked on page load, so a closed browser does not stay logged in.
- Hebrew name first and bold. The English name comes after it, smaller and lighter.
- Phones: cell first, then home.
- Every date input offers both the Jewish and the English calendar.
- An assignee (one of the team) can be set per account or task, with "who calls" dropdowns on rows. There is a quick "📝 נאטיץ" note button, and the last note is shown on rows.
- "Ask again" schedule per account:
  - Options: monthly, 3, 6 or 12 months, before each Yom Tov, one-time (`once`), or none.
  - Default for YG donors is the last gift plus the default frequency from Settings.
  - Settings has a "skipOnce" option, so donors who gave only once are not auto-scheduled.
- The logo has a 3D look done with CSS only (`.logo3d`: drop-shadow extrusion, shine, tilt). The image itself must never be changed.

## SMS bot (v1.6)
- `supabase/functions/sms/index.ts`: Supabase Edge Function `sms`, deployed by the user from the dashboard editor with **Verify JWT off**. Plain fetch to Supabase REST/Storage with the built-in `SUPABASE_SERVICE_ROLE_KEY`; caches the JLS data and the event log while warm.
- Works with **Telnyx** (JSON webhook, Ed25519 signature `TELNYX_PUBLIC_KEY`, reply via API `TELNYX_API_KEY`) or **Twilio** (form webhook, HMAC `TWILIO_AUTH_TOKEN`, TwiML reply). Requests without a valid signature get 403. Secrets live only in Supabase > Edge Functions > Secrets.
- Only phones in `team.phone` (SETUP.sql section 6) get answers. Commands (Yiddish/English): a plain name = info, `טעלעפאן`, `אדרעס`, `געגעבן` (last 12 months), `באלאנס`, `היינט`, `פלעדזשעס`, `געקאלט`, `טאדו`/`+` (new task for the sender), `נאטיץ name: text`, `שול`, `?`. Several matches → list of `#code`.
- Test locally: copy to `.mts` and run with `node --experimental-strip-types` against a mocked `fetch` (exports `handle`, `answer`, `load`).

## E-mail receipts (v1.8)
- `supabase/functions/email/index.ts`: Edge Function `email` (the owner's is named `EMAIL`), deployed with **Verify JWT OFF** (with the new API keys the legacy gateway check blocks the browser call; the function checks the user itself); checks the caller is in `team` via RLS (caller's token + `SUPABASE_ANON_KEY`), then sends through **Gmail SMTP** (`GMAIL_USER` + `GMAIL_APP_PASSWORD`, smtp.gmail.com:465 via a static `npm:nodemailer` import with a 20 s timeout – the owner sends from bt.maharit@gmail.com, works; opening the function URL in a browser (GET) shows which provider/secrets are set, never their values) or **Resend** (`RESEND_API_KEY`) or **Brevo** (`BREVO_API_KEY`), from `EMAIL_FROM` (optional `EMAIL_REPLY_TO`). Secrets only in Supabase.
- receipts.js: `emailOf(code)` = `acct.email` or JLS `a.em[0]`; `rcPdf(d)` renders the printed receipt page in a hidden iframe with html2canvas 1.4.1 + jsPDF 2.5.1 (cdnjs, loaded on first use) into a Letter PDF Blob, which is **uploaded to Storage** (`jls/receipts/<key>-<ms>.bin`, content type octet-stream, up to 3 tries – the owner's network sometimes drops uploads, PDFs especially); the function gets only `pdfPath`, downloads it with the service key, attaches it, then deletes it (a large request body to the function never arrived from the owner's network); `mailSend(to, subject, html, blob, filename, tag, cc)` is the shared sender (upload to Storage, then `sb.functions.invoke`); the function accepts several `to`/`cc` addresses (commas) and sets the attachment type from the file name (.pdf/.xlsx). `rcSendMail` calls `sb.functions.invoke` on `email`, falling back to `EMAIL` (the owner's function was created as **EMAIL**; the working name is remembered in localStorage `yg_mailfn`), then writes `rcpt.emailed` and a history note. ✉️ per row and bulk "✉️ שיק אימעיל". Subject/body settings `mailSubject`/`mailBody` with {name} {amount} {date}.
- Gmail SMTP from Supabase was verified live (2026-11-12, ~4 s with a 500 KB attachment); real receipts went out fine the same day.
- Claude can deploy functions and read logs itself: the `yg-fund` cloud environment holds a Supabase access token for `api.supabase.com` (proxy-injected). Deploy: `POST https://api.supabase.com/v1/projects/qrudivrakwoathgbzrwd/functions/deploy?slug=EMAIL` multipart (metadata `{entrypoint_path, name, verify_jwt:false}` + file). Logs: `GET …/analytics/endpoints/logs?sql=…` on the single `logs` table, filter `source in ('function_edge_logs','function_logs')`.
- Test: copy the function to `.mts` and run with `node --experimental-strip-types` against a mocked `fetch`; in Playwright route cdnjs to the npm copies (the sandbox cannot reach cdnjs).

## Automatic office e-mail (v1.12)
- `supabase/functions/fundmail/index.ts` (+ `xlsx.js`, a copy of the app's XLSX writer – TypeScript parsing chokes on it inline): Edge Function `fundmail`, Verify JWT off, needs header `x-cron-key` = secret `FUNDMAIL_KEY` (set by the owner; Claude may not set secrets or run SQL – both are blocked). Called daily by pg_cron + pg_net (SETUP.sql section 8, run by the owner). Sends the office e-mail for the last finished 2-week period when settings `frAuto` is on, today ≥ period end + `frAutoDays`, `frOffice` is set and `frmail[from]` is not sent yet; writes `frmail` (by "⏰ אויטאמאטיש") and closes the to-do. `?dry=1&key=…` shows what it would send. Deploy both files: multipart with two `file=@…` parts.
- With `frAuto` on, `ensureFundMailTask` adds no reminder.

## Click to call
- `callBtn(num, code)` in sections.js puts a 📞 link next to phones. The link template is per computer (localStorage `yg_call`, header button "📞 טעלעפאן"): Yealink preset = `http(s)://<phone IP>/servlet?key=number={digits}` (owner's phone is at 192.168.0.242; http refused, try https) (the owner's office phone; needs Action URI Allow IP List on the phone), default `tel:{num}` (opens the office softphone), or an http click-to-dial URL for desk phones (`{num}` = +1…, `{digits}` = 10 digits), opened in a small window that closes itself.
- The owner's office uses **TekLink** click-to-call: the JLS "CALL URL" line `https://users.theteklink.com/lic/clicktocall/v1/callPOSTJLSPOST<body>` means HTTP POST of `<body>` (`license_key=…&connect=%PhoneNum%`, PhoneNum = 10 digits). The app sends it as a hidden form POST into a small popup. The license key lives only in each computer's localStorage – **never commit it**. The setup has "שיקן ווי" (POST / GET / with a leading 1: `{num1}`) and a 🧪 test that keeps the popup open so the owner can read TekLink's answer (not yet confirmed which variant TekLink wants; our sandbox cannot reach that host).
